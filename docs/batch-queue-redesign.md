# 批量生成 · 队列化重设计（执行版）

本文档是对前几轮讨论的收敛，并采纳了产品视角评审的四项关键修正。核心机制不变，
改动集中在「入列这一刻」与「运行中这一段」的交互与呈现。

## 一、不变的骨架（已确认）

- 批量与否**不由 AI 判断**，由用户手动组装（点「加入队列」）。
- 队列 = 右侧第 4 个 tab；对话里只出现两头：方案卡 → 结果卡。
- 执行本质 = 方案快照 + 换种子；一批跑完聚合为**一张结果卡**。
- 批次标题 = 自动任务 ID（`B-8F3A2C`）。
- 种子策略默认 random，list/step/fixed 为进阶（展开菜单）。
- 旧 `BatchWorkspacePage` 表单式批量退役，参数组合扫描并入种子策略进阶。

## 二、评审后新增的四项修正（本次执行落实）

1. **入列即确认**：入列后 toast 明确「已加入队列 · 第 N 项 · 随机种子」，并标明
   是否带参考图。队列行内用缩略图徽标标识「带参考图」，不用文字猜测。
2. **拖拽分流去歧义**（阶段 3）：迷你条与提示词区两落点给出截然不同的高亮与
   悬浮文案；「覆盖」为破坏性动作，落点做得更小、更刻意；「入列」可撤销、落点更大。
3. **运行中不沉默**：方案卡自身升级为轻量状态锚点，从「已排队 → 运行中 x/y →
   完成」只更新这一张卡的一行状态，不产生新消息。
4. **部分成功必须可见**：结果卡分三区——成功画廊 / 失败槽位（带「重试失败项」）/
   批次汇总（成功 x/y · 耗时 · 批次 ID）。

## 三、统一对象模型（本次实现）

```
队列项 = {
  id,                     // 客户端 draft id
  plan: { positive, negative, workflowName, workflowDir,
          parameters, nodeOverrides, outputNodeIds, media },
  sourceKind: 'plan' | 'result' | 'preset',
  sourceLabel: string,    // 人类可读来源（方案卡 / 结果卡 / 预设卡 / 名称）
  hasReference: boolean,  // 是否带参考图（供队列行徽标与 toast）
  seedStrategy: { mode: 'random'|'list'|'step'|'fixed', ... },
}
```

入列来源与 payload：

| 来源 | payload | 默认种子策略 |
|---|---|---|
| 方案卡 / 预览弹窗 | 方案快照 | random ×4 |
| 结果卡 | 方案快照 + 强制换种子 | random ×4 |
| 预设卡 / 预设详情 | 完整配置（含 sourceImages 参考图） | random ×4 |

## 四、种子策略（用户语言）

| mode | 用户文案 | 解析 |
|---|---|---|
| random | 随机 ×N | N 个随机种子 |
| fixed | 固定 S | 单种子 S |
| list | 序列 a, b, c | 逐个种子 |
| step | 递增 start 起 +step ×N | start, start+step, … |

队列行与编辑面板**内联预览解析出的种子列表**，入列前即可看到会跑哪几张。

## 五、执行与呈现

```
方案卡/结果卡/预设卡/预览弹窗 ──加入队列──► 队列 tab（第4个）
                                            N 项 · 每项: 摘要+种子策略+参考图徽标
                                            [启动队列]
                                                    │ 每项按种子策略展开为 jobs
                                                    ▼
                                        batch-scheduler（复用现有引擎，逐任务换种子）
                                                    │ batch:event → 订阅刷新
                                                    ▼
                                    完成 → 聚合画廊结果卡（对话区底部）
                                    失败 → 右侧队列内单行重试 / 恢复面板衔接
```

- 队列草稿为客户端内存态（跨会话不持久，符合「一次性执行单」倾向）；已启动批次由
  主进程 `batch-scheduler` 持久化并支持重启恢复。
- 结果卡注入对话区底部（按完成时间），标题携带批次 ID 与来源，卡片内含
  「加入队列」可对结果再跑变体。

## 六、实施阶段

- **阶段 1（核心闭环）**：队列 tab、入列入口（方案/结果/预览）、种子策略、聚合结果卡、
  退役旧页。
- **阶段 2**：预设卡入列（含参考图）。
- **阶段 3（挂账）**：悬浮球队列迷你条、拖拽分流、悬浮球内预设入列。
- **阶段 4（挂账，可选）**：AI 展开器 / 变体强度滑杆（豆包千问式左下角）。

## 七、明确不做

- ❌ 意图分析判断批量
- ❌ 自动出 N 张变体（本地算力）
- ❌ 斜杠命令作为日常入口
- ❌ 借用现有卡片/弹窗交互
- ❌ `BatchWorkspacePage` 继续存在
- ❌ 悬浮球承载完整队列（只做入口 + 状态）
